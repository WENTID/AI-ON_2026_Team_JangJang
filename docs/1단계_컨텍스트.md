## 2. 판정 위계 재구성

### 원칙
- **큐싱 예방 수칙이 판정의 최상위 기준**이다. 기존 점수 규칙은 각 수칙 아래 소분류로 배치한다.
- 검사 워크플로우도 이 위계 순서로 진행하고, 결과 근거도 이 위계로 묶어 보여준다.
- 위계·매핑은 코드가 아닌 **설정 파일**(예: `rules_hierarchy.json`)로 관리한다.
- 기존 점수 계산 방식(확정/강한/약한 신호, 약한 신호 상한, 안전 신호 감점, 조합 규칙)은 유지한다.

### 대분류 초안 (⚠ 팀이 공식 예방 수칙 출처로 문구 확정 필요)
| 대분류 (예방 수칙) | 소분류 (기존 점수 기준) |
|---|---|
| 접속 주소가 공식 주소인지 확인 | 피싱 DB 등재(확정), 유명 브랜드 유사 도메인, 신규 도메인, IP 주소 URL, 단축 URL 리다이렉트, AI 사칭 판별, 약한 신호(긴 URL·서브도메인 과다·특수문자 등) |
| 개인정보·금융정보 입력 요구 주의 | 브랜드·도메인 불일치 로그인/결제 폼, http + 입력 폼 조합 |
| 앱 설치·파일 다운로드 유도 주의 | 실행 파일(.apk/.exe) 다운로드, 악성코드 DB 등재 |
| 출처가 불분명한 QR 주의 (덧붙인 스티커 등) | (2단계 맥락 일치 분석 자리) |
| 안전 근거 | 신뢰 상위 사이트, 오래된 도메인, 정상 인증서 |

- 연결 보안(http, 인증서 오류)은 기존처럼 단독으로 판정을 바꾸지 않는다.
- 같은 의미를 반복하는 검사·근거 문구는 **하나로 합친다**.

## 3. AI (1단계)
- **Gemini API 유지**, 용도는 기존대로 **페이지 사칭 판별(HTML 텍스트 분석)**
- AI 판단은 최종 판정이 아니라 **신호 하나**로만 반영 (기존 원칙 유지)
- **일관성 확보 (2차 멘토링 반영)**
  - AI가 검사 항목을 스스로 정하지 않는다. 프로그램에 정의된 **고정 질문 + 고정 JSON 스키마**로만 질의
  - temperature 0 (결정적 출력)
  - 같은 URL은 결과를 캐시해 재분석 시 같은 결과가 나오게 함 (가능하면)
- 기존과 동일: 신뢰 상위 사이트·피싱 DB 확정이면 AI 호출 생략, 실패 시 "AI 분석 불가" 후 규칙 결과로 판정
- AI 근거 해설 기능은 만들지 않는다. IT 용어는 짧은 정의 또는 외부 정의 링크로 대체 (여유 있을 때)

## 4. 화면 (모바일 웹)

### 입력
- **첫 화면 = 바로 카메라 스캔** (모바일 세로 화면 기준)
- 이미지 업로드, URL 직접 입력은 **보조 메뉴**로
- 카메라 인식 시 전체 프레임 저장은 기존대로 유지 (2단계 OCR용으로 재사용)
- 찍으면 중간 과정 없이 바로 결과 (스피너만)

### 결과
- 첫 화면: **판정(안전/주의/위험, 색상)** + **해당 예방 수칙 한 줄** + **행동 안내**(예: "접속하지 말고 공식 앱에서 확인하세요")
- 상세보기(펼침): 예방 수칙별로 묶인 근거, 점수, 원본/최종 URL, 기타 주의사항, 맥락 비교 자리("2단계 제공 예정")
- 중복 용어·표현 제거

### 주의
- 휴대폰 브라우저에서 카메라를 쓰려면 **HTTPS** 필요 → 시연은 PC로 하거나, 폰 시연 시 ngrok 등 HTTPS 터널 사용
