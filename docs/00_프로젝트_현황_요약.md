- 새 주제는 네트워크·보안 분야가 아니어도 된다고 봄

  - 회사별 데이터로 최적화되므로 업종 구분은 불필요, 시연 예시 직무는 전산 쪽
- 후보 2: **AI 기반 QR코드 피싱·악성 링크 판별 앱** (10/29) — QR 안내 문구와 실제 접속 페이지 목적의 일치 여부까지 확인
  - 문제의식: 국내 QR 활용이 홍보용에서 편의점·가게·상품 QR 결제로 급증 → URL 기반 피싱 분석기가 QR 기반으로 진화해야 함
- 두 후보에 대해 멘토에게 의견 요청 메일 (10/30)
- **QR피싱분석기로 결정**, Claude Code로 구현 (11/3)

## 설계 결정 (11/3)
- 이전 모바일프로그래밍2 과제 **TrustRoute**(Java·SQLite Android URL 파밍 검사 앱)의 설계·화이트리스트 재사용
- 웹으로 구현, 피싱 분석에 집중하고 피싱 외 결격사유는 부가 주의사항으로만 표시
- QR 안내문구 목적 ↔ 실제 사이트 목적 일치 판단을 핵심 기능으로 봄
- 점수 방식: 이전 프로젝트처럼 정책 배점 → 총점 구간 판정은 정상 사이트(네이버 등)도 걸리고 http라고 무조건 위험은 아니라 부적합. **위험 요소 + 안전 요소(정상 인증서·신뢰 상위 사이트)를 함께 계산**, http여도 입력폼이 없으면 위험하지 않으므로 상황 조합을 점수에 반영
- 판정 구조: 2트랙(피싱/유해성 동등 판정)은 난이도 상승·논점 흐려짐으로 폐기 → **피싱 판정 하나 + 기타 주의사항(악성코드 DB·실행파일 다운로드·연결보안) 부가 표시**
- 벤치마킹 반영: 카메라 QR 스캔 + QR 파일 업로드(드래그앤드롭), 중간 과정 없이 바로 결과, 결과에 위배된 논리정책을 근거로 제시
- AI 활용: 근거 해설에만 쓰기엔 아깝다고 봄. 문구의 사회공학 패턴 분석은 탐지율 낮고 비효율적이라 제외
- AI 계획: 1단계 = 접속 페이지 사칭 판별 + 카메라 스캔 시 전체 화면 저장 / 2단계 = QR 안내문구 목적 ↔ 실제 페이지 목적 일치 분석
- 사칭 판별은 HTML 텍스트 분석 먼저, 헤드리스 브라우저 세팅되면 스크린샷 분석 추가 (조건부)
- 구현 프롬프트: `QR피싱분석기_ClaudeCode_프롬프트.md`

## 멘토링 피드백 (2차, 11/4)
- AI API: Gemini → **Jev AI** ('dev'/'jev'라고 적으면 이것, Gemini Developer API 아님), **QR 맥락 일치·불일치 판별 전용**
- 안내문은 **OCR로 텍스트 추출**해 Jev AI에 전달 — **OCR 사용 확정**
- 대회 시연은 API 대신 Claude Code 로컬로도 충분, 개발 중 무료 모델 / 시연 때만 유료 모델 교체 가능
- **큐싱 예방 수칙을 판정 첫 기준**으로, 피싱 카테고리를 대분류(예방 수칙)·소분류(점수 기준)로 위계화
- AI 응답 변동성(같은 주소에 다른 결과) 대응: 검사 규칙은 프로그램이 정적으로 정의, AI는 정해진 질의에만 답함(하네스), AI 질의·검사 규칙 중복 제거로 경량화
- 앱 간소화·과정 단축(카메라 중심), 판정 근거는 상세보기로만
- 주제를 **피싱 분석기 → QR 분석기**로 확장: QR 목적(결제/웹 이동 등) 분류, 결과는 범죄유형 대메뉴 → 검사 카테고리 → 세부 항목 계층형 (백신 로그처럼 처음엔 위험도만), 결과 화면 중복 표현 제거
- AI 근거 해설은 지금 불필요, IT 용어는 정의 메모나 나무위키 등 링크로 대체
- 웹 → **앱 변경할 것 같음** (확정 전), 난이도 높으면 기존 웹 코드를 살린 웹앱 가능
- 발표: 실제 피싱 주소는 변형해 자료에만, 시연은 가짜 주소 (안전상 이유 강조)
- 마케팅 아이디어: 교내 홍보물 QR 대체 배포
- QR 피싱·정상 샘플 수집 필요

## 결정 사항 (11/15~11/16)
- **플랫폼: PWA(웹앱) 확정.** 네이티브 앱은 확장 계획으로 발표 (시간 남으면 Capacitor 등으로 APK 패키징 확인)
- **2단계 AI 구조 확정**: 1차 = OCR로 안내문 텍스트화 → Jev AI 맥락 일치 판별(항상), 2차 = 애매할 때만 조건부 멀티모달(원본 이미지 직접 분석). 1차를 먼저 완성하고 2차는 놓치는 사례 확인 후 추가, 시간 부족 시 확장 계획으로. 2차도 고정 스키마 하네스 안에서 동작. 중간보고서의 "상세 근거 제시"는 해설이 아니라 "추가 분석을 통한 결론 도출"이라는 의도로 정정
- **2차 대비 사전 준비**: 원본 이미지 끝까지 유지, 결과 스키마에 "이미지 분석" 칸 확보, 2차 호출 조건은 설정 파일로
- **Claude Code 활용 방침**: 기본은 API 유지, 로컬 Claude Code는 시연용 선택지. (2026-06-15부터 `claude -p`는 별도 월간 크레딧 소모, 결정성·속도·배포 한계 있음)

## 진행·결정 사항 (11/20)
- **PWA 구현 완료**: manifest·아이콘·서비스워커(`/sw.js`)·iOS 메타태그
- **Render 배포 완료 → 시연 방식 확정**: 고정 주소 배포로 시연, ngrok 안 씀. 무료 요금제는 잠들기 때문에 **시연 직전 접속해 깨워 둘 것**
