# 3차 멘토링 정리 (2026-11-23)

> 원본 메모: `docs/멘토링3차정리.txt` (본인 메모, 수정하지 않고 보존). 아래는 주제별로 재정리한 것이며, 메모가 짧아 해석이 갈리는 부분은 **⚠ 확인 필요**로 표시했다.

## 핵심 요약
1. **2차 검사는 전체 적용**하고, 맥락 비교만 따로 적용한다.
2. AI 호출이 느리다(최소 10초) → 더 빠른 AI로 바꾸거나, **끝난 검사 항목부터 순차 표시**한다.
3. **AI 검사 배점**: 대메뉴마다 최대 점수를 두고 항목별 배점을 분리한다. 치명적 결함(킬 스위치)이면 무조건 위험. 점수는 **높을수록 위험**으로 변경.
4. 디자인이 심각 → 외부 의견을 받는다(특히 "Claude 티 나는" 시각 디자인).

## 1. 2차 검사 적용 범위
- **결정: 2차 검사를 전체 적용하고, 맥락 비교만 분리 적용한다.**
  - 지금 구현은 안내문을 읽어 목적 비교를 한 경우(포스터형)에만 2차(`app/cross_check.py`)를 호출함 → 전체 적용으로 바뀌면 이 호출 조건이 달라진다.
- 전체 적용의 장단점: AI를 쓰므로 탐지율은 오르지만 모든 검사 시간이 늘어난다.
- **속도 문제**: AI의 처리 속도보다 **AI를 호출하는 시간 자체가 최소 10초**.
  - 대안 ① 호출이 빠른 AI로 교체 ② **로딩 중에 처리가 끝난 검사 항목부터 순차 표시**

## 2. 맥락 비교
- 비교 기준(탐색 범위, 참/거짓을 내기 위한 입력값을 정하는 기준)이 문제 → **먼저 Jev의 성능을 파악**한다. Jev가 처리 과정에서 알아서 구분할 수 있으면 해결.
- **단순 QR로 보고 맥락 비교를 생략하는 기준**: 텍스트 외에 도형·배치까지 판별해야 하는가? → **VLLM(시각 모델)이 필요한지** 검토.
  - 현재: QR 면적 비율 60% 이상 + Gemini 읽기 결과로 생략 (Gemini 멀티모달이 이미 사진을 봄)

## 3. AI 검사 기준 (하네스)
- **필수 워크플로우는 설정으로** 둔다.
- **AI 판단 근거는 사람이 사후 분석한 뒤 결과를 출력하는 방식.**
- 1차 검사 내용의 중복 제거는 하지 않는다(필요함). 규칙을 지정하는 게 아니라 **탐색 방향을 지정하는 정도**로 한다.
  - **팀 결정 (11/27): "AI(2차)가 1차 항목을 빼지 않고 다시 검사한다"로 해석 확정.** 1차 항목을 제외하면 유사 상황까지 빠져 미탐이 늘고, 같은 상황에서도 규칙과 AI의 결과가 다를 수 있기 때문에 더블체크가 신뢰성에 유리하다. 호출 횟수가 같으면 시간 차이는 작다고 추정(측정은 구현 후).
  - **1차와 2차는 독립적으로 판단한다.** AI에게 1차 결과를 보여주지 않는다(보여주면 같은 결론을 되풀이함). 프로그램이 두 결과를 비교한다.
  - **불일치 처리**: ① 규칙 위험·AI 안전 → 점수를 깎지 않고 "AI 의견 불일치"만 표시 ② 규칙 안전·AI 위험 → 대분류별 상한 안에서 가산 ③ 둘 다 위험 → 신뢰도 높음 표시
  - **출력 고정(같은 입력에 같은 답)은 나중에 하네스 처리로 해결**한다.

## 4. AI 검사 점수
- **대메뉴(대분류)마다 최대 점수를 부여해 항목별 배점을 분리**한다.
- 단, **치명적 결함(킬 스위치)이 발생하면 무조건 위험 판정**으로 보완한다.
- **AI 검사 항목별 점수는 우리가 직접 부여**해야 한다.
- 역할 분담(멘토 의견): 1차 검사에서 탐지 항목을 최대한 늘리고, 2차 검사는 맥락 비교처럼 AI만 할 수 있는 것을 기준으로 탐지한다. → **팀은 3절 결정에 따라 2차도 1차 항목을 재검사(더블체크)한다.**
- **점수 판정 기준을 "높을수록 위험"으로 변경**한다.
- 이 결정으로 2단계 컨텍스트의 "2차 점수 반영 방식 미결정"이 풀린다. `display_only`(표시만)는 부적합하고, 대분류별 상한이 있는 점수 반영 방식을 구현해야 한다.

## 5. 결과 화면
- AI 검사 항목은 결과 분석에 따로 있으므로 **최종 결과에서 중복으로 띄우지 않고 제거**한다.

## 6. 발표·확산·배포
- 1차 검사 항목은 **이 정도면 충분**하다.
- 발표 전에 **장난 포스터 배포**.
- **앱인토스에 배포**해 보기.
- **ChatGPT 등 범용 AI와의 차별성** 강조.
- **각 도구 선택 이유 공부(질문 방어)**: 왜 Gemini·Jev·PWA·Render 등을 골랐는지 답할 수 있어야 한다.

## 7. 디자인
- 디자인이 지금 심각하다. **외부 의견이 필요**하다.
- 기능적 디자인도 문제지만 **너무 Claude 티가 나는 시각 디자인이 더 문제**.
- 방침: **문제되는 것만 먼저 고치고, 전체는 나중에.**

## 9. 팀 결정 추가 (11/27)

- **2차 검사를 둘로 분리한다.**
  - **AI 검사**: 모든 입력에 적용 (URL 직접 입력 포함). 1차 항목도 재검사(3절).
  - **맥락 비교 검사**: **복합 QR(안내문 등 주변 맥락이 함께 찍힌 QR)에만** 적용. 단순 QR은 생략(기존 생략 기준 유지).
- **AI 검사 점수 판정**
  - 대메뉴마다 배점(최대 점수)을 부여하고, **AI 검사도 하나의 대메뉴**로 둔다.
  - 그 안의 **세부 점수는 AI 자체 판단**으로 정한다. 단, 대메뉴 최대 점수를 넘지 못한다. 치명적 결함(킬 스위치)은 무조건 위험(4절).
  - 같은 입력에 AI가 점수를 다르게 줄 수 있다(2차 멘토링에서 지적한 일관성 문제). 멘토는 "AI 검사 항목별 점수는 우리가 부여"를 권했음. 그렇다고 AI가 찾을 항목을 전부 우리가 정하면 AI가 필요 없어짐 → **아래 고정+자율 구조로 정리 (11/27 팀 제안)**
- **AI 검사 구조: 고정 항목 + 자율 영역 (11/27)**
  - **고정 항목**: 우리가 지정할 수 있는 항목은 항목별 점수를 우리가 정한다.
  - **자율 영역**: 탐색 방향만 정하고(기존 `settings.cross_check.perspectives`), 어떤 항목이 걸릴지는 AI가 찾는다. 이 영역 **전체에 하나의 최대 점수**를 부여하고, 그 안에서만 반영한다.
  - 자율 영역의 심각도는 점수 대신 '낮음/중간/높음' 등급으로 받고 환산은 설정 파일에서 한다(흔들림을 자율 영역 안에 가둠). 인용 근거 검증(원문에 없으면 제외)은 유지.
  - AI가 자주 찾는 유형은 사람이 검토해 고정 항목으로 승격할 수 있다(확장 아이디어).
  - 세부 수치(영역별 상한, 등급 환산표)는 구현 때 정한다.

- **사칭 판별은 AI 검사에 흡수 (11/27)**: 1단계 Gemini 페이지 사칭 판별(`ai_impersonation`·`ai_brand_claim`·`ai_brand_mismatch`)은 피싱 판별과 같은 기능이므로 새 AI 검사(모든 입력에 적용)에 합친다. 기준선 수치(탐지율 40.0→80.7%)는 흡수 후 재측정한다.
- **결과 표시**: 끝난 항목부터 순차 표시하지 않고, **로딩 화면만** 둔다(11/27). AI 호출이 최소 10초 걸리는 점은 감수한다.
- **대메뉴 구성 (확정 11/27)**: 주소 확인 / 정보 입력 / 앱·파일 설치 / AI 검사(사칭 판별·자율 영역·**맥락 비교 포함**) / 안전 근거(감점 전용). 맥락 비교는 별도 대메뉴로 빼지 않는다.
- **점수 방식 (확정 11/27)**: 정규화가 아니라 **대메뉴별 배점(합계 100)을 상한으로 둔 합산**. 대메뉴는 자기 배점을 넘지 못한다. 해당 없는 항목은 `-`로 표시. 배점 수치와 임계값은 나중에 구현 후 1단계 검증을 다시 돌려 정한다.
- **킬 스위치 (확정 11/27)**: `phishing_db`, `malware_db`, 그리고 **맥락 비교의 강한 불일치**(불일치 확률 0.8 이상). 맥락 비교를 킬 스위치로 두는 대신 AI 검사 배점은 늘리지 않는다. 안내문 읽기 실패(readable=false, 8자 미만)·접속 실패 페이지면 발동하지 않는다. 약한 신호(0.5~0.8)는 점수로 반영. ⚠ 스티커·교차 분석을 킬 스위치에 넣을지는 미정(기본은 점수 처리). 정상 안내문 사진에서의 오탐을 재검증에서 측정할 것.
